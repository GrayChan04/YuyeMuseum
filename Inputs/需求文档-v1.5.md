# 榆野博物馆 · 项目需求文档 v1.5

> 版本：v1.5（2026-08-31）
> 状态：需求已确认，进入开发
> 维护者：馆主
> 版本说明：本文件是 V1.5 的完整实施依据。与旧版冲突时以本文件为准；旧版文档仅保留为设计演变记录。

---

## 1. 项目目标

榆野博物馆是由喻言粉丝自发建立的线上博物馆。网站以关键词馆藏和时间轴整理喻言与粉丝群体之间的梗、出处、变化与共同记忆，让新朋友能够补上语境，也让一路同行的朋友随时回来重看。

V1.5 的目标是把现有演示站整理为可以开始录入真实内容的正式前端，同时完成小草坪及各类提交的完整交互原型。

- 移除全部虚构馆藏、演示留言、演示意见和演示媒体。
- 以 0 件正式馆藏、0 棵公开小草作为上线初始状态。
- 统一品牌、版头、字号、内容宽度和滚动条。
- 把小草坪改造成按日期生长、可筛选和可回看的草地。
- 恢复留言、意见、回复和版权反馈表单的完整前端交互。
- 建立可复用的数据格式、录入指南和构建前内容校验。

## 2. 技术边界

### 2.1 本版采用

- Vue 3、Vite、Vue Router、JavaScript。
- GitHub Pages 和现有 GitHub Actions 发布流程。
- Hash 路由，确保 GitHub Pages 刷新子页面时不依赖服务器重写。
- 仓库内 JSON 维护已经公开的馆藏、小草和馆主的话。
- 仓库 `public` 目录保存正式图片、音频和本地存档依据。
- 零新增运行时依赖；内容校验仅使用 Node.js 内置模块。

### 2.2 本版不采用

- 数据库、Supabase 或其他外部数据服务。
- 真实文件上传、邮件发送、GitHub Issue 代投或本地持久化。
- 访客账号、馆主登录、审核后台或内容管理后台。
- 访问统计、自动通知、在线审核和实时互动。

表单必须可填写、可校验、可预览附件，但校验通过后只明确告知内容没有发送或保存。不得制造成功状态、伪造新草、清空用户输入或写入 localStorage/sessionStorage。

## 3. 页面与公共结构

| 页面 | Hash 路径 | 主要内容 |
|---|---|---|
| 首页 | `/#/` | 品牌版头、搜索、馆藏入口 |
| 馆藏详情 | `/#/keyword/:id` | 馆藏介绍、时间轴、节点详情 |
| 小草坪 | `/#/lawn` | 日期草地、筛选、日历、提交原型 |
| 建馆说明 | `/#/about` | 建馆用途、声明、准则、馆主的话 |
| 未知页面 | 任意未知 Hash 路径 | 站内 404 |

固定导航只显示 `首页 / 小草坪 / 建馆说明`。左侧品牌入口同时显示 Logo 和 `榆野博物馆`，返回首页；导航始终固定在视口顶部。

## 4. 品牌与全站视觉

### 4.1 Logo

- `Y` 在左侧，`U` 在右上，`E` 在右下。
- Y 的右分支与 U 左端直接连接，共同形成连续建筑骨架。
- 斜屋顶向两侧延伸约 8–10 个 SVG 单位，把三个字母完整包在屋檐下。
- 不增加水平短檐、下垂短线、台阶短线或零碎装饰。
- 保持单色深绿、圆角描边和小尺寸清晰度。

### 4.2 版头与内容宽度

- 首页、小草坪、建馆说明和馆藏详情使用统一版头高度。
- 桌面目标：`clamp(340px, 52svh, 520px)`。
- 手机目标：`clamp(320px, 52svh, 440px)`。
- 文字放大或内容确实放不下时允许自然增高，不裁切内容。
- 导航、版头、首页搜索、馆藏、小草坪和建馆说明使用同一套最大 1180px 外框。
- 小草坪继续保留暖纸底和浅绿草景，不能重新变成与其他页面割裂的整块高饱和绿色。

### 4.3 字号与字体

- 首页主标语独立于内页标题，不与内页 H1 共用字号。
- 内页 H1 统一一个层级。
- 正文 15–16px，版头与段落导语 16–17px，界面文字 14px，辅助文字 13px，时间和元数据不小于 12px。
- 四类版头导语、标题和叙事正文使用衬线字体。
- 导航、按钮、表单、筛选、日期和元数据使用无衬线字体。
- 删除散落的 9–11px 微小字号，200% 文字缩放下仍能完整操作。

### 4.4 滚动条与动态效果

- 页面、搜索结果、抽屉、对话框和日历使用约 8px 的暖纸色细滚动条。
- 滑块为苔绿色圆角，悬停时加深；兼容 Firefox 与 WebKit。
- 横向时间轴继续隐藏自身滚动条。
- 尊重 `prefers-reduced-motion`，取消非必要平滑动画但保留定位结果。

## 5. 首页

### 5.1 正式文字

- 馆名：`榆野博物馆`
- 两行主标题：
  - `那些掉落的回忆`
  - `在这里再看一遍`
- 导语：`沿着时间逆溯，一点一点拾起、联系，再讲起。`

馆名、主标题和导语适当增加字间距，手机端收紧到不溢出。

### 5.2 搜索与重复吸附

- 搜索栏位于首页首屏中下部，而不是版头后的普通内容起点。
- 访客在首屏轻微向下滚动、触摸上滑或使用向下键时，页面自动滚到搜索栏吸附在导航下方的位置。
- 返回首屏后可以再次触发，不能只在第一次有效。
- 浏览馆藏区时不拦截普通滚动。
- 输入框、按钮或链接获得焦点时不劫持按键。
- 搜索区下方不增加贯穿页面的分隔线。
- 默认提示文字为 `搜索关键词或别名`。

### 5.3 馆藏区域

- 标题：`馆藏`。
- 副文案：`当前收录 N 件馆藏`，N 直接读取 `keywords.json`，不得硬编码。
- 有馆藏时，桌面四列、平板两列、手机一列。
- 0 件馆藏时不显示假卡片、演示卡或额外空状态，只保留标题和动态数量。

### 5.4 搜索无结果

无结果时显示：

> 暂时没有找到『关键词』。或许，你也希望博物馆收藏它？

按钮为 `去小草坪告诉馆主`。点击后进入：

`/#/lawn?intent=collection-suggestion&keyword=...`

小草坪自动选择意见、打开表单，并以只读方式预填：

> 希望榆野博物馆收藏『关键词』。

关键词去除首尾空白并限制为 50 字。关闭抽屉后移除已经消费的意图参数，刷新不得反复打开。

## 6. 馆藏详情

### 6.1 馆藏介绍

- 桌面采用左右布局：左侧是返回入口、馆藏名称和简介；右侧是始见时间、别名和经典出处。
- 手机按上述顺序纵向堆叠。
- 始见时间和节点时间都接受年、年月、年月日三级精度。
- `isApproximate: true` 时在日期前明确显示“约”。
- 介绍与时间轴之间不增加横向贯穿页面的分隔线。

### 6.2 时间轴

- 时间轴为单行横向排列，节点按时间从早到晚排序。
- 圆点几何中心必须落在横线中心，不增加列表上下边线、节点竖线或整列底色。
- 初始不展开节点。
- 只通过点击控制：点击节点展开；再次点击当前节点收起；点击其他节点切换。
- 鼠标悬停和键盘聚焦只能提示可操作，不能自动展开。
- 溢出时允许横向触摸或滚动；聚焦节点时保证其进入可视区域。

### 6.3 节点媒体与来源

- 图片直接展示，旁边标注来源平台、账号、标题和原链接。
- 音频使用 `public` 内本地文件和浏览器原生播放器。
- 视频只提供外部平台链接，不在站内嵌入播放器。
- 详情版头中的经典出处与节点来源使用相同的链接状态和存档依据规则。
- 正常来源使用 `status: "active"`。
- 原链接失效时使用 `status: "unavailable"`，显示“原链接已失效”，并且必须存在可信网页存档 URL 或 `public` 内截图/PDF 存档依据。
- 每条来源旁提供 `链接失效？告诉馆主`，点击后用馆藏 ID、节点 ID 和来源 ID 打开意见表单；路由不得信任外部传入的任意预填正文。

### 6.4 404

不存在的馆藏：

- `当前藏品还未收纳。`
- `你可以回到入口，重新挑选一件馆藏。`

普通未知路径：

- `这个房间还没开放。`
- `你可以回到入口，重新挑选一件馆藏。`

两者按钮均为 `返回博物馆首页`。

## 7. 建馆说明

用途说明：

> 榆野博物馆由粉丝自发建立。我们沿着时间逆溯，辨认出处，整理变化，把那些散落的重新拾起，再放到所有人能够看见的地方。这里为新朋友们补上语境，也为一路同行的老朋友们留下随时可以回看的地方。

免责声明另起一段：

> 本馆与艺人本人及经纪公司无关；馆内素材版权归原作者所有，馆中所藏来自有限的记录与视角，只是共同记忆的一隅，不代表完整故事。

三条准则：

1. **核实后入馆**：每条馆藏尽量核对发生时间、原始出处和上下文；暂时无法确认的内容会明确标注，不作为定论。
2. **清楚标注出处**：图片、音频、视频和文字资料尽量注明原平台、发布账号与可访问链接，方便查证和版权反馈。
3. **对新朋友友好**：用简明介绍、别名说明和时间轴补足背景，不把熟悉粉丝语境当作阅读前提。

准则下方增加 `馆主的话`：

- 数据来自 `curator-notes.json`，按日期倒序完整显示。
- 每则只显示日期和一两句话，不折叠、不进入详情页、不显示“查看更多”。
- 第一则日期为 `2026-08-31`，正文为 `榆野博物馆从这里开始。谢谢你来这里看看我们共同经历过的回忆。`

## 8. 小草坪

### 8.1 版头与基本结构

- 标题：`小草坪`。
- 导语：`留下的话是一棵小草，随着时间慢慢长高。`
- 主体顶部放置 `留下一棵小草` 和 `留下一棵意见小草` 两个按钮。
- 留言与意见在同一片草地显示，使用 `全部 / 留言 / 意见` 筛选，默认 `全部`。
- 已公开且未隐藏的内容始终可查；180 天不是删除期限。

### 8.2 日期草地和日历

- 按 Asia/Shanghai 的自然日分地块，日期由新到旧。
- 默认展示最近 180 个自然日中有内容的日期，包括当天。
- 每个日期默认显示当前筛选下最新 32 棵主草；回复不计入 32。
- 超过 32 棵时显示 `展开当天全部 N 棵`，展开后可 `收起到 32 棵`，不分页。
- 桌面日历吸附在右侧；手机日历位于草地前，默认折叠。
- 日历提供年份、月份选择和前后月按钮；有内容的日期才标记，标记随筛选变化。
- 最近 180 天内点击日期时滚到对应地块；更早日期进入单日视图，并可 `回到最近 180 天`。

### 8.3 草的表达和详情

- 一次留言或意见是一棵主草，多句话不拆分；回复是长在主草旁的新芽。
- 留言是苔绿色细叶草，意见是偏暖黄绿色穗草，馆主回复是带 `馆` 标记的深绿新芽。
- 同时使用形状和文字标识类型，不能只依赖颜色。
- 草高、叶片方向和轻微偏移由内容 ID 固定计算，刷新后不得随机跳动。
- 保持可读顺序的响应式网格：桌面四列、平板三列、手机两列，极窄或 200% 放大时一列。
- 未展开时显示匿名/昵称和单行摘录。
- 点击后在当前日期地块下方展开全文；全页同时只展开一棵。再次点击收起，点击其他草切换。
- 留言允许任意层级回复，视觉最多缩进两层；更深回复显示 `回复 @某人`。
- 回复按时间正序显示，并保留在原始主留言日期，不因跨日回复移动主草。
- 意见不开放访客相互回复；通过审核后可先公开，未获馆主回复时显示 `等待馆主回复`。
- 所有时间显示为 `YYYY.MM.DD HH:mm`，按北京时间换算。
- 正文中的普通 http/https 链接自动安全链接，不解析 HTML。
- 主草和回复具有稳定分享链接；打开后定位日期、展开所属主草并聚焦目标回复。
- 附图显示缩略图网格，点击进入支持关闭、键盘和触摸切换的灯箱。

### 8.4 空状态

0 棵草时仍显示操作按钮、筛选器和没有日期标记的日历，并显示：

- `第一棵草还没长出来。`
- `提交功能开放后，留下的话会在这里按日期慢慢生长。`

## 9. 提交表单原型

### 9.1 抽屉公共规则

- 桌面从右侧打开，手机占满屏幕。
- 支持遮罩点击、Esc 关闭、焦点锁定、关闭后归还焦点、页面滚动锁定和移动端安全区。
- 表单已有文字或附件时，关闭前询问 `要放弃尚未发送的内容吗？`，按钮为 `继续填写 / 放弃并关闭`。
- 校验成功后保留全部输入并显示：`当前版本尚未连接提交服务，你填写的内容没有发送或保存。`

### 9.2 留言

- 标题：`留下一棵小草`。
- 说明：`可以匿名，也可以留下昵称；通过审核后，会出现在草坪上。`
- 默认匿名；关闭匿名后显示昵称，最多 20 字。
- 留言最多 500 字。

### 9.3 意见

- 标题：`留下一棵意见小草`。
- 说明：`意见始终匿名；通过审核后会公开在草坪上，馆主会逐条回复。`
- 意见最多 500 字，不提供昵称字段。
- 搜索建议和失效来源反馈都使用意见表单及受信任的只读预填内容。

### 9.4 回复

- 标题：`回应这棵草`。
- 说明：`通过审核后，你的回复小草会长在这棵草旁边。`
- 默认匿名；昵称和正文限制与留言相同。

### 9.5 留言、意见和回复附图

- 最多 3 张，每张最多 5MB。
- 只接受 JPG、PNG、WebP。
- 支持本地缩略图、文件大小提示和逐张移除，不支持上传或拖拽排序。
- 选图后必须勾选：`我确认有权分享这些图片，且其中不含需要隐藏的个人信息。`

## 10. 版权反馈

页脚保留非官方与版权声明及 `版权反馈` 入口，表单使用同一套抽屉。

说明：

> 如需更正署名、补充来源或申请移除素材，请填写以下信息。馆主会认真核对，并按情况更正、补充或移除。

隐私说明：

> 版权反馈中的身份、联系方式、情况说明和附件仅用于核对，不会公开在小草坪。

规则：

- 必选类型：更正署名 / 补充来源 / 申请移除。
- 相关馆藏或页面、联系方式、情况说明始终必填。
- 只有申请移除需要填写身份或权利关系。
- 可附最多 5 个 JPG、PNG、WebP 或 PDF；单文件最多 10MB，总计最多 30MB。
- 从馆藏详情打开时自动带入相关页面，但允许修改。
- 文件只做本地校验和预览，提交后显示统一的未发送提示。
- 身份、联系方式、说明和附件属于私密材料，不写入小草坪公开数据。

## 11. 数据与构建校验

- `src/data/keywords.json` 的正式初始结构为 `{ "keywords": [] }`。
- `src/data/community.json` 的正式初始结构为 `{ "messages": [], "opinions": [] }`。
- `src/data/curator-notes.json` 保存馆主的话。
- 删除 `public` 下全部 `demo-*` 资产。
- 详细字段、模板和媒体目录规则见《内容录入指南 v1.5》。
- `npm run validate:content` 检查 JSON 结构、必填项、日期、重复 ID、重复名称/别名、URL、媒体文件、失效来源依据、回复父级和循环关系。
- `npm run build` 通过 `prebuild` 自动先执行内容校验；空馆藏和空草坪是合法状态。
- 内容校验失败时必须中止构建并输出可定位到数组项和字段的错误。

## 12. 验收标准

1. 正式数据中不存在虚构馆藏、演示留言、演示意见、`isDemo` 字段或 `demo-*` 媒体。
2. 首页显示确认后的正式导语，馆藏数量为动态 0，且没有假卡片或多余空状态。
3. 首页搜索在返回首屏后可重复吸附；搜索无结果能把关键词安全带到意见抽屉。
4. 四类页面版头、1180px 外框、字号体系和滚动条一致。
5. Logo 的 Y 与 U 连成骨架，斜屋顶完整覆盖 YUE，且没有多余短线。
6. 馆藏时间轴圆点居中，点击展开/收起/切换正确，未恢复丑陋的横贯分隔线。
7. 小草坪空状态、三种筛选、日期日历、32 棵折叠和旧日期单日视图均可处理空数据与临时测试数据。
8. 多层回复、跨日回复、未回复意见、分享定位、安全链接和图片灯箱符合本文规则。
9. 四类表单可操作、可校验、可预览附件；校验后明确没有发送或保存，并保留输入。
