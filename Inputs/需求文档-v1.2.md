## 1. 项目定义与版本边界

### 1.1 一句话定位

榆野博物馆是由喻言粉丝自发建立的线上展示馆，以关键词和时间轴整理喻言与粉丝群体之间的梗、出处及共同记忆，帮助新朋友快速理解相关语境，也让一路相伴的朋友保存值得记住的片段。

### 1.2 V1.2 核心目标

1. 跑通“浏览或搜索关键词 → 进入馆藏 → 按时间阅读发展历史”的核心路径。
2. 用四件完整的演示馆藏验证内容结构，不编造真实粉圈历史。
3. 通过“小草坪”展示留言、回复、匿名意见和馆主回复的未来形态。
4. 在 GitHub Pages 上稳定运行，并兼顾桌面端、移动端和微信内置浏览器。

### 1.3 V1.2 技术边界

- 使用 Vue 3、Vite、Vue Router、JavaScript 和仓库内 JSON。
- 使用 Hash 路由，并通过 GitHub Actions 发布到 GitHub Pages。
- 不接入数据库、账号系统、馆长后台、统计系统或第三方提交服务。
- 留言、意见和版权反馈表单仅展示未来流程；按钮禁用，不发送或保存输入内容。
- 不把可写 GitHub 仓库的令牌放入浏览器，也不宣称尚未开放的反馈通道已经可用。

## 2. 全站框架与视觉规则

### 2.1 页面与路径

| 页面 | Hash 路径 | 核心职责 |
|---|---|---|
| 首页 | `/#/` | 首屏主张、搜索、部分馆藏入口 |
| 关键词详情 | `/#/keyword/:id` | 关键词简介、横向时间轴与节点详情 |
| 小草坪 | `/#/lawn` | 留言墙、意见箱及未来提交表单 |
| 建馆说明 | `/#/about` | 简要说明建馆目的、立场与原则 |

保留 `/#/about` 路径以兼容已有链接，但导航文字、页面标题和浏览器标题统一使用“建馆说明”。未知路径和不存在的馆藏显示站内 404，并提供返回首页入口。

### 2.2 固定导航

- 导航始终固定在视口顶部，滚动页面时不离开。
- 左侧只显示 YUE 房屋骨架 Logo，点击返回首页；不显示馆名或英文副标题。
- 右侧仅显示 `首页｜小草坪｜建馆说明`。
- 当前页面只通过文字颜色加深和字重增加表示，不使用下划线或底部指示条。
- 页面首内容、吸顶搜索、站内锚点和其他 sticky 元素均须避开导航高度，不得被遮挡。

### 2.3 全站视觉减法

- 删除装饰性英文眉题，包括页面、板块、弹窗和空状态中的同类文案。
- 删除装饰性序号，包括 `001`、`01 / 02`、馆藏编号和节点编号。
- 日期、时间、内容数量和 404 等有实际含义的数字不属于装饰序号，可正常保留。
- 继续使用暖黄、黄绿色、纸张感和现代艺术馆气质，但减少大面积装饰、重复说明和无功能入口。
- 所有交互保留清晰的键盘焦点；尊重 `prefers-reduced-motion`。

### 2.4 紧凑页脚

- 页脚显著降低高度，只保留一层内容。
- 左侧显示一行声明：`本馆由粉丝自发建立，与艺人官方及经纪公司无关；馆内素材版权归原作者所有。`
- 右侧保留“版权反馈”按钮，打开现有反馈弹窗。
- 删除馆名、英文副标题、年份、第二层底栏和重复品牌信息。
- 手机端可自然换成两行，但不得横向溢出。

## 3. YUE 房屋骨架 Logo

### 3.1 设计目标

Logo 第一眼是一座极简建筑，第二眼能辨认出 `Y`、`U`、`E`；房屋感必须由字母笔画本身形成，不能在字母外再套独立房框。

### 3.2 构图

- 建议 SVG 画布比例约 `5:4`，参考 `viewBox="0 0 120 96"`。
- `Y` 位于左侧并占主要高度：上方分叉参与屋顶结构，下方主干形成左侧承重线。
- `U` 位于右上：两条竖向笔画和底部弧线形成上层空间、拱窗或回廊感。
- `E` 位于右下：竖线和三条横线形成下层墙体、层板与建筑底座。
- 三个字母至少有两处共享或自然衔接的笔画，不得成为三个彼此分离的字符。
- 不添加独立屋顶、外框、烟囱、圆点、门把手或其他装饰。

### 3.3 线条与颜色

- 单色、等线宽、圆角端点与圆角连接；参考主线宽 `5–6px`。
- 不使用填充色块、阴影或渐变。
- 默认深绿色 `#273823`；需要深色背景版本时使用暖米色 `#F7F1DC`。
- 导航桌面宽度约 `42–46px`，手机约 `36–40px`；小尺寸下优先保证 Y/U/E 可辨认。
- favicon 使用同一骨架的简化版本，不另造一套图形语言。

## 4. 首页

### 4.1 首屏

- 首屏占满固定导航以下的第一个视口，首次进入时看不到搜索框。
- 只保留居中的两行大字和一行小字，水平、垂直居中排版。
- 当前文案为易替换的临时占位内容，馆主后续可直接修改；手机端小字允许自然换行。
- 删除编号、英文眉题、插画、Logo 展台、按钮、滚动提示和其他说明。

### 4.2 首屏滚动与搜索吸顶

- 搜索框位于首屏之后的第二部分。
- 用户从首屏首次轻微向下滚动时，页面执行一次平滑吸附，使搜索框正好位于固定导航下方。
- 完成首次吸附后恢复正常滚动，不反复抢夺滚轮或触摸手势。
- 用户继续浏览部分馆藏时，搜索框保持吸附在固定导航下方；到达其所属区域末端后自然结束。
- 开启减少动态效果偏好时，不使用平滑动画，改为即时定位。

### 4.3 搜索框与搜索行为

- 搜索区域只显示放大镜、输入框、候选结果和无结果提示。
- 删除“搜索一件馆藏”、可见的 Enter 按键图示及其他辅助标签；占位文字暂用“搜索关键词或别名”。
- 搜索名称和别名，使用去除首尾空格后的包含匹配；英文不区分大小写。
- 输入时实时展示候选；支持上下键选择、Esc 关闭、点击候选进入。
- 仍保留键盘回车功能：进入当前候选，未选择时进入第一条结果。
- 不记录搜索内容或搜索次数。

### 4.4 部分馆藏

- 板块标题为“部分馆藏”，说明仅显示“当前开放 4 件演示馆藏”。
- 首页展示四件内容完整的演示馆藏，不制作空卡片。
- 桌面端使用四列紧凑小卡片网格；平板两列，手机一列。
- 卡片只显示关键词名称、一句简短说明和起始月份。
- 不显示“馆藏／演示馆藏”小标记、编号、“查看时间轴”或大面积装饰；整张卡可点击进入。
- 删除“去小草坪坐坐”和“读一读建馆说明”两个额外入口块。

## 5. 关键词详情与时间轴

### 5.1 紧凑简介

- 顶部只保留返回首页的轻量链接、关键词名称、一至两句介绍。
- 基础信息只显示始见月份、别名和经典出处。
- 删除馆藏编号、演示标签、英文眉题、馆藏员手记、装饰性引用和大面积橱窗布局。

### 5.2 横向时间轴

- 简介后直接显示一条单行横向时间轴，不显示“发展时间轴”、英文标题或操作说明。
- 节点按时间从早到晚排列，只显示年月、圆点和简短标题。
- 桌面端节点较少时均匀铺开；节点超出宽度时允许横向滚动。
- 手机端保持单行横向滑动，并提供轻微滚动吸附，不折成多行。
- 初始不展开任何节点详情。
- 所有设备统一使用点击：点击节点展开，重复点击当前节点收起，点击其他节点直接切换。
- 当前节点须有清晰选中状态，并通过 `aria-expanded`、`aria-controls` 等属性表达展开关系；不依赖鼠标悬停。

### 5.3 节点详情与媒体

- 详情紧贴时间轴下方，使用轻微高度与透明度动画展开或收起。
- 只显示节点标题、年月、正文、实际存在的媒体和出处。
- 删除 `SELECTED NODE`、节点编号、左侧日期展签、圆形装饰和大面积独立背景。
- 图片直接展示，并标注来源平台、账号及原链接。
- 音频保存在仓库内，使用浏览器原生播放器，并标注来源。
- 视频不下载、不内嵌，只提供外部平台播放链接和来源信息。
- 缺失媒体字段不占位；外部链接在新标签页打开并带安全属性。
- 删除“下一件馆藏”区域。

## 6. 小草坪

### 6.1 首屏与分区

- 保留“小草坪”标题、简短说明和小草图形。
- 删除英文眉题、装饰编号、“试开放中”标签、首屏底部分隔线和小草图形下的地平线。
- 内容区分为“留言墙”和“意见箱”两个标签，不显示 `01 / 02`。
- 标签旁显示动态内容数量，格式为 `n 条`；该数量是信息，不是装饰序号。
- 当前标签状态须明确，并支持鼠标、触摸与键盘操作；左右方向键切换，Home/End 跳至首末标签，焦点与 ARIA 状态同步。

### 6.2 留言墙

- 展示 2 条静态演示主留言，其中至少一条包含完整三层对话。
- 主留言最新优先；同一对话内回复按时间正序。
- 留言可表现为署名或匿名，所有留言与回复显示北京时间 `YYYY.MM.DD HH:mm`。
- 视觉最多缩进三层，更深关系仍归入第三层并显示“回复 @对象”。
- 页面不在每条留言或回复旁重复显示“演示”徽章；首屏说明统一交代当前内容为演示。

### 6.3 意见箱

- 展示 2 条静态匿名演示意见，每条均包含馆主回复。
- 意见按最新优先；意见与馆主回复均显示北京时间。
- 页面不在每条意见旁重复显示“演示”徽章。
- 不展示复杂处理状态。

### 6.4 筹备中表单

- 留言表单保留匿名选项、昵称和留言字段；意见表单只保留意见字段。
- 清楚显示“互动功能筹备中”和“本版本不会发送或保存填写内容”。
- 提交按钮保持禁用，任何输入都不得被发送或持久化。
- 桌面端表单位于内容右侧并可随页面滚动，但必须避开固定导航。
- 手机端先显示留言／意见内容，再显示对应的筹备中表单。

## 7. 建馆说明、404 与版权反馈

### 7.1 建馆说明

页面只保留以下三部分，不增加大型首屏、二级标题、Logo 展台、长篇双栏说明或底部 CTA：

1. 页面标题：`建馆说明`。
2. 一段合并说明，原文固定为：

   > 榆野博物馆由粉丝自发建立，试着把散落在榆野色记忆里的关键词、出处与发展脉络一一拾起、整理、陈列，让新朋友由此走近喻言，也读懂喜欢她的人们之间的默契；让一路相伴的老朋友，在这里留住那些曾经鲜亮的回忆。本馆与艺人本人及经纪公司无关；馆内素材版权归原作者所有，馆中所藏来自有限的记录与视角，只是共同记忆的一隅，不代表完整故事。

3. 三条极短原则：`核实后入馆 / 清楚标注出处 / 对新朋友友好`。原则不带编号，不附长解释。

### 7.2 404 与不存在的馆藏

- 保留中文错误标题、简短解释和返回首页入口。
- 404 错误码可以保留，因为它具有实际含义。
- 删除 `ROOM NOT FOUND`、`COLLECTION NOT FOUND` 等装饰性英文眉题。

### 7.3 版权反馈

- 页脚“版权反馈”继续打开站内弹窗。
- 弹窗保留素材链接、权利人身份、联系信息和情况说明等未来字段。
- 提交按钮禁用，并明确说明当前不会发送或保存内容。
- 删除装饰性英文眉题，不作“已经可以直接联系馆长”的承诺。

## 8. 数据与兼容性

### 8.1 数据接口

- 沿用 `keywords.json` 与 `community.json` 的既有字段，不进行破坏性数据迁移。
- 关键词继续保留 `aliases`、`summary`、`startTime`、`intro`、`origin`、`nodes` 等字段。
- 时间轴节点继续支持正文、来源、图片、本地音频和外部视频链接。
- 留言继续以 `parentId`、`replyToName` 表达回复关系；意见继续包含 `curatorReply`。
- `isDemo` 字段可继续保留在数据中，但本轮界面不在每张卡片或每条小草坪内容旁重复渲染徽章。

### 8.2 响应式与浏览器

- 桌面重点验收 1280px 及以上；移动端重点验收 375px、390px，并保证 320px 起无横向溢出。
- 支持当前主流 Chrome、Edge、Safari 及 Android/iOS 微信内置浏览器；不支持 Internet Explorer。
- 固定导航、搜索吸附、横向时间轴、弹窗和小草坪表单在触摸设备上均须可正常操作。
