## 1. 项目定义

### 1.1 一句话定位

榆野博物馆是喻言粉丝自发建立的线上展示馆，用时间轴整理喻言及粉丝群体之间的粉圈黑话和有趣的梗，帮助新粉快速认识喻言、理解粉丝群体的共同记忆。

### 1.2 核心用户与价值

- 新粉：搜索关键词，快速看懂一个梗的出处和发展脉络。
- 老粉：浏览被系统整理的图片、音频、切片出处与历史节点。
- 馆主：以仓库数据维护馆藏，为后续真实互动和内容扩充建立基础。

### 1.3 V1 产品目标

1. 建立可在 GitHub Pages 稳定运行的响应式展示网站。
2. 跑通“发现关键词 → 搜索或点击 → 阅读完整时间轴”的核心路径。
3. 完成“小草坪”的互动界面和数据模型，以静态演示数据验证阅读体验。
4. 建立清晰的数据维护、构建和部署流程，使内容扩充不需要修改页面代码。

### 1.4 V1 非目标

- 不接入 Supabase、Firebase 或其他外部数据库。
- 不开放真实访客提交、审核和馆主后台。
- 不提供真实版权反馈提交，避免伪装成已可用功能。
- 不记录搜索次数，不自动计算热门关键词。
- 不开发投稿、账号、多管理员、数据统计或自定义域名。
- 不编纂未经馆主确认的真实粉圈历史。

## 2. V1 交付范围

### 2.1 页面清单

| 页面 | Hash 路径 | 核心职责 |
|---|---|---|
| 首页 | `/#/` | 品牌展示、关键词搜索、馆藏入口 |
| 关键词时间轴 | `/#/keyword/:id` | 展示单个关键词的简介、出处与发展历史 |
| 小草坪 | `/#/lawn` | 展示留言墙、意见箱及未来提交界面 |
| 关于本馆 | `/#/about` | 说明定位、建馆原则和版权立场 |

未知路径和不存在的关键词需显示站内 404 状态，并提供返回首页入口。

### 2.2 公共框架

- 顶部导航：`首页｜小草坪｜关于本馆`。
- 当前页面有明确选中状态。
- Logo 与馆名可点击返回首页。
- 全站页脚包含非官方声明、素材版权说明和版权反馈入口。
- 页脚版权入口打开站内反馈弹窗；V1 表单可见但禁用提交，并明确说明通道筹备中。

## 3. 首页

### 3.1 页面结构

1. Logo、馆名与建馆主张组成的首屏展签区。
2. 大搜索框；滚动离开首屏后吸顶。
3. 已开放馆藏卡片区。
4. 小草坪与关于本馆的辅助入口。
5. 页脚。

### 3.2 V1 馆藏数量

- 只展示 2 个内容完整的演示关键词。
- 每个关键词至少包含简介、经典出处、馆藏说明和 3 个时间轴节点。
- 演示内容必须明确标识为演示，不得伪装成真实粉圈史。
- 不制作另外 8 个空卡片；数据结构支持后续扩充到 10 个以上。

### 3.3 搜索行为

- 搜索范围：关键词名称和别名。
- 匹配方式：去除首尾空格后的包含匹配；英文不区分大小写。
- 输入时实时显示候选项。
- 点击候选项或按回车进入第一条匹配结果。
- 无结果时显示友好空状态，不记录搜索行为。
- 需支持键盘上下选择、回车进入和 Esc 关闭建议列表。

### 3.4 馆藏卡片

每张卡片展示：

- 关键词名称；
- 一句话梗概；
- 起始月份；
- “演示馆藏”标记；
- 进入时间轴的明确操作提示。

## 4. 关键词时间轴页

### 4.1 橱窗简介

展示关键词名称、一句话解释、经典出处、俏皮馆藏说明、别名与“始见于 YYYY.MM”。

### 4.2 时间轴

- 纵向展示，节点按年月从早到晚排列。
- 节点显示年月、标题和短摘要。
- 默认选中最早节点并展示详情。
- 点击节点后更新选中样式与详情，并平滑滚动到详情区。
- V1 不将选中节点写入 URL。

### 4.3 节点详情

节点支持以下可选组合：

- 正文段落；
- 图片：直接展示，必须标注来源平台、来源账号，尽量附原链接；
- 音频：文件保存在仓库内，使用网页原生播放器，标注来源；
- 视频：不内嵌、不下载，只展示外部平台名称、账号、封面（可选）和跳转链接；
- 普通出处链接。

缺失的媒体字段不占位；外部链接在新标签页打开并带安全属性。

## 5. 小草坪

### 5.1 页面结构

- 页面名称：小草坪。
- 两个标签：`留言墙` 与 `意见箱`。
- 每个标签均包含内容列表和未来提交表单。
- V1 表单字段可交互展示，但提交按钮禁用，并明确显示“互动功能筹备中”。

### 5.2 留言墙规则

- 主留言支持匿名或署名展示。
- 留言支持回复以及“回复的回复”。
- 数据结构以 `parentId` 记录关系。
- 视觉最多缩进 3 层；超过视觉层级的回复仍归入第三层，并显示“回复 @对象”。
- 所有主留言和回复显示发布时间。
- 主留言按最新到最早排列；同一会话内回复按最早到最晚排列。

### 5.3 意见箱规则

- 所有意见统一显示为“匿名访客”，不显示昵称字段。
- 所有公开意见都必须带馆主回复。
- 意见与馆主回复均显示发布时间。
- V1 不展示复杂处理状态，仅以是否有馆主回复作为后续真实系统的约束。
- 意见按最新到最早排列。

### 5.4 V1 演示数据

- 2 条演示主留言，其中至少一条完整展示三层回复。
- 2 条演示意见，每条均带馆主回复。
- 所有演示内容显示“演示”标记，避免与真实访客内容混淆。
- 时间统一按北京时间格式 `YYYY.MM.DD HH:mm` 展示。

### 5.5 后续真实互动约束

后续开放提交时，主留言、所有回复和意见都必须先审核后公开；馆主回复无需二次审核。真实提交必须接入安全的数据服务，禁止在浏览器中放置可写 GitHub 仓库的访问令牌。

## 6. 关于本馆与版权反馈

### 6.1 关于本馆

- 不介绍馆主个人身份。
- 说明本馆由粉丝独立维护，与艺人官方及经纪公司无关。
- 说明整理目的、馆藏范围与演示内容边界。
- 强调对素材出处和原作者权益的尊重。

### 6.2 版权反馈弹窗

界面包含：素材链接、权利人身份说明、联系信息、情况说明。

V1 行为：

- 表单仅用于展示未来流程。
- 提交按钮禁用。
- 清楚显示“版权反馈通道筹备中，正式运营前开放”。
- 页脚不得写出“可直接联系删除”等与实际能力不符的承诺。

## 7. 品牌与视觉

### 7.1 名称与 Logo

- 名称：榆野博物馆。
- Logo 字母来源：YUYE。
- 构图：Y 在左，U 在右上，E 在右下，整体形似博物馆房屋。
- 交付独立 SVG 矢量文件，线条简洁，一眼能辨认字母结构。

### 7.2 视觉关键词

现代艺术馆、暖黄、黄绿色、温暖复古、留白、展签、纸张与馆藏编号感。

### 7.3 响应式

- 设计覆盖桌面、平板和手机。
- 桌面重点验收 1280px 及以上。
- 手机重点验收 375px、390px，并保证 320px 起不横向溢出。
- 支持当前主流 Chrome、Edge、Safari 和 Android/iOS 微信内置浏览器。
- 不支持 Internet Explorer。
- 尊重 `prefers-reduced-motion`，键盘焦点清晰可见。

## 9. 技术与部署

- Vue 3 + Vite + Vue Router。
- 使用 JavaScript 与仓库内 JSON 数据，避免 V1 引入不必要的服务端复杂度。
- Hash 路由规避 GitHub Pages 刷新子路径 404。
- GitHub Actions 在推送默认分支后构建并发布 Pages。
- Vite `base` 使用相对路径，使默认用户站点和项目站点都能加载资源。
- 提供 README：本地启动、内容更新、构建、建仓、推送、启用 Pages 和故障排查。
- GitHub 认证使用浏览器授权、SSH 或访问令牌；馆主不得将密码发送给开发者或写入仓库。

## 10. V1 验收标准

1. `npm install`、`npm run build` 成功，产出可部署静态文件。
2. 首页、两个演示关键词、小草坪、关于本馆及 404 状态均可访问。
3. 搜索名称或别名能实时匹配、键盘选择并跳转；无结果有清晰提示。
4. 每个关键词至少 3 个节点，默认选中首节点；切换节点能显示完整详情并滚动到详情区。
5. 页面组件支持带出处的图片、本地音频和外部视频链接，不内嵌外部视频。
6. 小草坪能展示 2 条演示留言、三层回复、2 条已获馆主回复的演示意见和北京时间。
7. 所有提交按钮明确禁用，不产生“数据已经保存”的误导。
8. 版权反馈弹窗可打开和关闭，明确说明通道尚未开放。
9. 导航、Logo、页脚及响应式布局全站一致；320px 无横向溢出。
10. 交付 YUYE 房屋形 SVG Logo，并满足基本键盘操作、焦点可见和减少动画偏好。
11. GitHub Actions Pages 工作流语法完整，README 给出连接仓库和部署步骤。
