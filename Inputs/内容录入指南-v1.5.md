# 榆野博物馆 · 内容录入指南 v1.5

> 适用版本：v1.5
> 更新日期：2026-08-31
> 目的：帮助馆主在不修改页面代码的情况下，安全录入已经核实并可以公开的馆藏、小草和馆主的话。

---

## 1. 录入前须知

1. 只录入已经核实、允许公开的内容。待审核留言、意见、版权身份材料和联系方式不能写入这些 JSON。
2. 不确定的时间可以降低精度或标记为约略，不能为了格式完整而编造日期。
3. 每张图片、每段音频、每个视频和每条文字依据都要保留来源。
4. 原链接失效时必须有可信网页存档或本地截图/PDF 依据，否则暂不入馆。
5. 修改后先运行 `npm run validate:content`，再运行 `npm run build`。
6. JSON 不允许注释、尾随逗号或中文引号。保存为 UTF-8。

正式数据文件：

| 文件 | 内容 |
|---|---|
| `src/data/keywords.json` | 馆藏和时间轴 |
| `src/data/community.json` | 已公开留言、回复和意见 |
| `src/data/curator-notes.json` | 馆主的话 |
| `public/media/` | 正式图片、音频和存档依据 |

建议按馆藏建立目录，例如：

```text
public/media/
└── keyword-id/
    ├── images/
    │   └── first-scene.webp
    ├── audio/
    │   └── original-clip.mp3
    └── archives/
        └── removed-post.png
```

JSON 中只写相对于 `public` 的路径，例如 `media/keyword-id/images/first-scene.webp`，不要写磁盘绝对路径。

## 2. 通用格式

### 2.1 ID

- 只使用小写英文字母、数字和连字符。
- 不能以连字符开头或结尾。
- 发布后不要修改，否则旧分享链接和来源反馈定位会失效。
- 馆藏 ID 全站唯一；同一馆藏内的节点 ID 唯一；所有来源 ID 全站唯一；所有留言、回复和意见 ID 彼此唯一。

推荐把上级 ID 作为前缀：

```json
{
  "id": "keyword-short-name",
  "nodeId": "keyword-short-name-first-seen",
  "sourceId": "keyword-short-name-first-seen-weibo-post"
}
```

上例只解释命名方式，不是可直接放入数据文件的对象。

### 2.2 日期与时间

馆藏与节点允许三种精度：

```json
"time": "2024"
```

```json
"time": "2024-06"
```

```json
"time": "2024-06-18"
```

约略时间另写布尔字段：

```json
{
  "time": "2024-06",
  "isApproximate": true
}
```

确定时间可省略 `isApproximate`，或设为 `false`。

留言、回复和意见必须使用带北京时间偏移的完整 ISO 时间：

```json
"createdAt": "2026-08-31T14:30:00+08:00"
```

馆主的话只使用自然日：

```json
"date": "2026-08-31"
```

### 2.3 链接

- 只接受完整 `https://` 或 `http://` 链接。
- 不写 `javascript:`、短代码或 HTML。
- 链接失效不等于删除 URL；如仍知道原 URL，可以保留并把状态设为 `unavailable`。

## 3. 录入一件馆藏

正式馆藏数据保存在 `src/data/keywords.json` 数组中。每个数组项用馆藏名称作为键，馆藏内容使用 [keywordTemplete.json](../src/data/keywordTemplete.json) 的结构：

```json
[
  {
    "馆藏名称": {
      "aliases": ["别名"],
      "description": "馆藏简介",
      "coverimagepath": "YuyeMuseum/src/data/coverimages/馆藏封面.jpg",
      "tags": ["标签"],
      "startdate": "2024-06",
      "nodes": []
    }
  }
]
```

- `aliases`、`tags` 可以是空数组；`description` 和 `coverimagepath` 可以为空。
- `startdate` 和节点 `date` 使用 `YYYY`、`YYYY-MM` 或 `YYYY-MM-DD`，不能为了补全而猜日期。
- 封面放在 `src/data/coverimages/`，`coverimagepath` 可以写仓库路径；页面会自动解析并打包。
- 每个节点包含 `date`、`title`、`description` 和 `sources`。空描述允许保留，页面不会生成空段落。
- 节点按日期从早到晚显示；同一天按 JSON 中的录入顺序显示。

## 4. 录入节点来源

每个节点可以有多个来源。来源使用以下结构：

```json
{
  "isexist": "true",
  "caption": "原帖或媒体说明",
  "format": "picture",
  "url": "https://example.com/original-post",
  "screenshotpath": "media/keyword-id/evidence/node.png"
}
```

- `format` 使用 `picture`、`video` 或 `audio`。文字类原帖按 `picture` 处理。
- `isexist` 表示原平台路径是否仍然有效，实际录入使用布尔值 `true` 或 `false`；页面也兼容字符串形式。
- `isexist: true` 时，`url` 填原平台链接，点击来源跳转微博、B站等外部平台；`screenshotpath` 不作为第二条来源。
- `isexist: false` 时，页面转到馆内资源，优先使用 `screenshotpath`；没有馆内截图时显示凭证缺失提示。
- 原平台链接和馆内截图属于同一个来源，页面只显示一条来源入口。截图存在时会在节点详情中预览，点击可以放大。
- `caption` 为空时，页面使用对应媒体类型的通用说明。来源地址和截图路径都为空时显示“出处待补充”。
- `picture` 显示图片；`video` 只显示外部播放链接；本地 `audio` 使用浏览器原生播放器并提供下载入口。
- 来源顺序按 JSON 保留，来源不会自动合并或删除。

本地图片、截图和音频必须位于 `src/data/` 或 `public/` 中，并使用受支持的 JPG、PNG、WebP、MP3、M4A、AAC、OGG、WAV 格式。视频不下载到仓库，也不嵌入站内。

## 6. 录入已经公开的小草

`community.json` 顶层始终保持：

```json
{
  "messages": [],
  "opinions": []
}
```

这里仅保存已经审核、允许所有访客公开查看的内容。待审核内容和版权反馈不得放入该文件。

### 6.1 主留言

```json
{
  "id": "message-20260831-example",
  "parentId": null,
  "replyToName": null,
  "author": "访客昵称",
  "isAnonymous": false,
  "content": "<完整留言，最多 500 字>",
  "createdAt": "2026-08-31T14:30:00+08:00",
  "attachments": [
    {
      "src": "media/lawn/message-20260831-example/image-1.webp",
      "alt": "<附图描述>"
    }
  ]
}
```

匿名留言设为：

```json
{
  "author": "匿名访客",
  "isAnonymous": true
}
```

### 6.2 回复

回复和主留言放在同一个 `messages` 数组，通过 `parentId` 指向直接回复对象：

```json
{
  "id": "reply-20260831-example",
  "parentId": "message-20260831-example",
  "replyToName": "访客昵称",
  "author": "匿名访客",
  "isAnonymous": true,
  "content": "<回复正文，最多 500 字>",
  "createdAt": "2026-08-31T15:10:00+08:00",
  "attachments": []
}
```

- 回复的时间不能早于父留言或父回复。
- `parentId` 必须存在，且不能形成自己回复自己或多条回复首尾相接的循环。
- 任意深度都用同一结构；页面只在视觉上限制为两级缩进。
- 跨日回复仍属于最初主留言所在的日期地块。

### 6.3 匿名意见

馆主尚未回复：

```json
{
  "id": "opinion-20260831-example",
  "content": "<公开意见，最多 500 字>",
  "createdAt": "2026-08-31T16:00:00+08:00",
  "attachments": [],
  "curatorReply": null
}
```

馆主已经回复：

```json
{
  "id": "opinion-20260831-example",
  "content": "<公开意见，最多 500 字>",
  "createdAt": "2026-08-31T16:00:00+08:00",
  "attachments": [],
  "curatorReply": {
    "content": "<馆主回复，最多 500 字>",
    "createdAt": "2026-08-31T18:30:00+08:00"
  }
}
```

意见始终匿名，不添加昵称或访客回复。馆主回复时间不能早于意见时间。

### 6.4 公开附图

- 一条留言、回复或意见最多 3 张。
- 每张图片不能超过 5MB。
- JSON 使用 `attachments` 字段；旧 `images` 字段只为代码兼容，不用于新录入。
- 只接受仓库 `public` 内的 JPG、PNG、WebP。
- 附图已经通过版权和隐私确认后才可公开。

## 7. 录入馆主的话

`curator-notes.json` 使用：

```json
[
  {
    "date": "2026-08-31",
    "content": "榆野博物馆从这里开始。谢谢你来这里看看我们共同经历过的回忆。"
  }
]
```

新增一则时，在数组增加对象：

```json
{
  "date": "2026-09-15",
  "content": "<一两句话的短公告>"
}
```

页面会按日期倒序显示，不必手动调整数组顺序。

## 8. 校验与发布前检查

对话式研究草稿不直接写入正式数据。研究文件放在被 Git 忽略的 `Research/`，使用以下命令检查和预览；只有馆主在研究 JSON 中记录批准决定后，才使用 `--write` 导出：

```bash
npm run validate:research -- Research/<馆藏英文ID>.json
npm run export:collection -- Research/<馆藏英文ID>.json
npm run export:collection -- Research/<馆藏英文ID>.json --write
```

导出按馆藏名称、节点日期和标题合并，不会自动删除已发布节点；导出前会对完整正式数据重新校验，失败时不写入。详细的搜索、冲突判断和停止条件见 [馆藏收集流程](馆藏收集流程.md)。

只校验内容：

```bash
npm run validate:content
```

完整构建：

```bash
npm run build
```

`npm run build` 会自动先执行内容校验。校验器主要检查：

- JSON 能否解析，顶层结构是否正确。
- 必填字段、字符长度和布尔字段类型。
- 馆藏名称和别名是否相互重复。
- 日期是否真实存在、时间是否带 `+08:00`。
- URL 是否为 http/https。
- 本地封面、截图和媒体是否存在且格式受支持。
- 原平台失效时是否有馆内截图路径。
- 留言回复父级是否存在、时间是否倒置、关系是否循环。
- 意见的馆主回复是否早于意见。
- 是否误留 `isDemo` 字段或 `public/demo-*` 文件。

校验错误会写出类似 `keywords[0].nodes[1].sources[0].url` 的位置。修正所有错误后再提交和推送。

发布前还应人工确认：

1. 内容语境准确，没有把猜测写成事实。
2. 账号、平台和原链接与素材一致。
3. 图片替代文字能够说明画面。
4. 素材没有泄露个人信息。
5. 页面中实际点击过时间轴、音频、视频外链和来源反馈入口。
6. 手机和电脑端都检查过排版。

## 9. 不应写入公开数据的内容

- 尚未审核的留言、回复或意见。
- 被拒绝、隐藏或因风险删除的内容。
- 版权反馈中的真实姓名、联系方式、身份关系、证件或举证附件。
- GitHub 密码、访问令牌、Cookie 或任何账号凭据。
- 没有依据的传闻、为了补齐时间轴而猜测的日期。
- 仅用于测试页面的虚构馆藏、演示留言和 `demo-*` 文件。

V1.5 没有馆主后台。真实提交、审核、私密材料保存和自动发布必须等后续版本选定安全后端后重新设计，不能通过修改本指南绕过这一边界。
