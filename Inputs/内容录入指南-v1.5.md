# 榆野博物馆 · 内容录入指南 v1.5

> 适用版本：v1.5
> 更新日期：2026-08-31
> 目的：帮助馆主在不修改页面代码的情况下，安全录入已经核实并可以公开的馆藏、小草和馆主的话。

---

## 1. 录入前须知

1. 只录入已经核实、允许公开的内容。待审核留言、意见、版权身份材料和联系方式不能写入这些 JSON。
2. 不确定的时间可以降低精度或标记为约略，不能为了格式完整而编造日期。
3. 每张图片、每段音频、每个视频和每条文字依据都要保留来源。
4. 原链接失效时必须有可信网页存档或本地截图/PDF 依据，否则暂不入馆。
5. 修改后先运行 `npm run validate:content`，再运行 `npm run build`。
6. JSON 不允许注释、尾随逗号或中文引号。保存为 UTF-8。

正式数据文件：

| 文件 | 内容 |
|---|---|
| `src/data/keywords.json` | 馆藏和时间轴 |
| `src/data/community.json` | 已公开留言、回复和意见 |
| `src/data/curator-notes.json` | 馆主的话 |
| `public/media/` | 正式图片、音频和存档依据 |

建议按馆藏建立目录，例如：

```text
public/media/
└── keyword-id/
    ├── images/
    │   └── first-scene.webp
    ├── audio/
    │   └── original-clip.mp3
    └── archives/
        └── removed-post.png
```

JSON 中只写相对于 `public` 的路径，例如 `media/keyword-id/images/first-scene.webp`，不要写磁盘绝对路径。

## 2. 通用格式

### 2.1 ID

- 只使用小写英文字母、数字和连字符。
- 不能以连字符开头或结尾。
- 发布后不要修改，否则旧分享链接和来源反馈定位会失效。
- 馆藏 ID 全站唯一；同一馆藏内的节点 ID 唯一；所有来源 ID 全站唯一；所有留言、回复和意见 ID 彼此唯一。

推荐把上级 ID 作为前缀：

```json
{
  "id": "keyword-short-name",
  "nodeId": "keyword-short-name-first-seen",
  "sourceId": "keyword-short-name-first-seen-weibo-post"
}
```

上例只解释命名方式，不是可直接放入数据文件的对象。

### 2.2 日期与时间

馆藏与节点允许三种精度：

```json
"time": "2024"
```

```json
"time": "2024-06"
```

```json
"time": "2024-06-18"
```

约略时间另写布尔字段：

```json
{
  "time": "2024-06",
  "isApproximate": true
}
```

确定时间可省略 `isApproximate`，或设为 `false`。

留言、回复和意见必须使用带北京时间偏移的完整 ISO 时间：

```json
"createdAt": "2026-08-31T14:30:00+08:00"
```

馆主的话只使用自然日：

```json
"date": "2026-08-31"
```

### 2.3 链接

- 只接受完整 `https://` 或 `http://` 链接。
- 不写 `javascript:`、短代码或 HTML。
- 链接失效不等于删除 URL；如仍知道原 URL，可以保留并把状态设为 `unavailable`。

## 3. 录入一件馆藏

`keywords.json` 顶层始终保持：

```json
{
  "keywords": []
}
```

把新馆藏对象放入 `keywords` 数组。下面是一份字段模板；尖括号内容必须换成真实资料，不能原样提交：

```json
{
  "id": "<馆藏稳定 ID>",
  "name": "<馆藏名称>",
  "aliases": ["<别名一>", "<别名二>"],
  "summary": "<首页卡片使用的一句简介>",
  "startTime": "2024-06",
  "isApproximate": false,
  "intro": "<详情版头使用的完整简介>",
  "origin": {
    "label": "<经典出处的简短名称>",
    "url": "https://example.com/original",
    "status": "active"
  },
  "nodes": [
    {
      "id": "<节点稳定 ID>",
      "time": "2024-06",
      "isApproximate": false,
      "title": "<节点标题>",
      "summary": "<节点的一句摘要>",
      "body": [
        "<第一段正文>",
        "<第二段正文>"
      ],
      "sources": [],
      "images": [],
      "audio": [],
      "videos": []
    }
  ]
}
```

注意：

- `aliases` 可以是空数组，但名称和所有别名不能与其他馆藏的名称或别名重复。
- 正式馆藏至少有一个节点；节点四个媒体/来源数组即使为空也要保留。
- `body` 是段落数组，至少一段；不要把整篇文字塞进带换行符的单个字符串。
- `origin.url` 暂时没有可访问链接时可以省略或写空字符串；`origin.label` 仍然必填。
- 经典出处链接失效时，把 `origin.status` 改为 `unavailable`，并增加 `archiveUrl` 或 `archiveAsset`；校验规则与下文失效来源相同。
- 不再使用 `curatorNote`、`isDemo` 等旧演示字段。

## 4. 录入来源

### 4.1 正常来源

所有节点文字来源以及图片、音频和视频的 `source` 都使用同一结构：

```json
{
  "id": "keyword-node-platform-account",
  "platform": "微博",
  "account": "真实发布账号",
  "label": "原帖标题或内容说明",
  "url": "https://example.com/original-post",
  "status": "active"
}
```

- `id` 必须在全站所有来源中唯一，以便“链接失效？告诉馆主”准确定位。
- 正常来源必须有可访问的 http/https 原链接。
- 同一依据不要既放在 `sources` 又作为媒体来源重复展示；放在实际展示它的位置即可。

### 4.2 原链接失效但有网页存档

```json
{
  "id": "keyword-node-platform-account",
  "platform": "微博",
  "account": "真实发布账号",
  "label": "原帖标题或内容说明",
  "url": "https://example.com/original-post",
  "status": "unavailable",
  "archiveUrl": "https://web.archive.org/example"
}
```

### 4.3 原链接失效但有本地依据

```json
{
  "id": "keyword-node-platform-account",
  "platform": "微博",
  "account": "真实发布账号",
  "label": "原帖标题或内容说明",
  "url": "https://example.com/original-post",
  "status": "unavailable",
  "archiveAsset": "media/keyword-id/archives/original-post.png"
}
```

本地存档依据只接受 JPG、PNG、WebP 或 PDF。请先确认保存和展示该依据不会侵犯隐私或带来额外版权风险。

## 5. 录入节点媒体

### 5.1 图片

正式馆藏图片只使用 JPG、PNG 或 WebP：

```json
{
  "src": "media/keyword-id/images/first-scene.webp",
  "alt": "<不依赖看见图片也能理解的简短描述>",
  "source": {
    "id": "keyword-node-image-source",
    "platform": "微博",
    "account": "真实发布账号",
    "label": "图片出处说明",
    "url": "https://example.com/original-image-post",
    "status": "active"
  }
}
```

`alt` 描述画面本身，不写“图片”“照片”等无信息词，也不塞入版权长文。

### 5.2 音频

音频必须先放入 `public/media/.../audio/`，网页使用浏览器原生播放器：

```json
{
  "src": "media/keyword-id/audio/original-clip.mp3",
  "title": "<音频标题>",
  "source": {
    "id": "keyword-node-audio-source",
    "platform": "微博",
    "account": "真实发布账号",
    "label": "音频出处说明",
    "url": "https://example.com/original-audio-post",
    "status": "active"
  }
}
```

支持 MP3、M4A、AAC、OGG 和 WAV。优先使用体积适中、主流浏览器兼容良好的 MP3 或 M4A。

### 5.3 视频外链

视频不下载到仓库，也不嵌入站内：

```json
{
  "title": "<视频标题>",
  "url": "https://www.bilibili.com/video/example",
  "source": {
    "id": "keyword-node-video-source",
    "platform": "哔哩哔哩",
    "account": "真实发布账号",
    "label": "视频出处说明",
    "url": "https://www.bilibili.com/video/example",
    "status": "active"
  }
}
```

用户点击后前往原平台播放。不要在 `public` 中放视频文件。

## 6. 录入已经公开的小草

`community.json` 顶层始终保持：

```json
{
  "messages": [],
  "opinions": []
}
```

这里仅保存已经审核、允许所有访客公开查看的内容。待审核内容和版权反馈不得放入该文件。

### 6.1 主留言

```json
{
  "id": "message-20260831-example",
  "parentId": null,
  "replyToName": null,
  "author": "访客昵称",
  "isAnonymous": false,
  "content": "<完整留言，最多 500 字>",
  "createdAt": "2026-08-31T14:30:00+08:00",
  "attachments": [
    {
      "src": "media/lawn/message-20260831-example/image-1.webp",
      "alt": "<附图描述>"
    }
  ]
}
```

匿名留言设为：

```json
{
  "author": "匿名访客",
  "isAnonymous": true
}
```

### 6.2 回复

回复和主留言放在同一个 `messages` 数组，通过 `parentId` 指向直接回复对象：

```json
{
  "id": "reply-20260831-example",
  "parentId": "message-20260831-example",
  "replyToName": "访客昵称",
  "author": "匿名访客",
  "isAnonymous": true,
  "content": "<回复正文，最多 500 字>",
  "createdAt": "2026-08-31T15:10:00+08:00",
  "attachments": []
}
```

- 回复的时间不能早于父留言或父回复。
- `parentId` 必须存在，且不能形成自己回复自己或多条回复首尾相接的循环。
- 任意深度都用同一结构；页面只在视觉上限制为两级缩进。
- 跨日回复仍属于最初主留言所在的日期地块。

### 6.3 匿名意见

馆主尚未回复：

```json
{
  "id": "opinion-20260831-example",
  "content": "<公开意见，最多 500 字>",
  "createdAt": "2026-08-31T16:00:00+08:00",
  "attachments": [],
  "curatorReply": null
}
```

馆主已经回复：

```json
{
  "id": "opinion-20260831-example",
  "content": "<公开意见，最多 500 字>",
  "createdAt": "2026-08-31T16:00:00+08:00",
  "attachments": [],
  "curatorReply": {
    "content": "<馆主回复，最多 500 字>",
    "createdAt": "2026-08-31T18:30:00+08:00"
  }
}
```

意见始终匿名，不添加昵称或访客回复。馆主回复时间不能早于意见时间。

### 6.4 公开附图

- 一条留言、回复或意见最多 3 张。
- 每张图片不能超过 5MB。
- JSON 使用 `attachments` 字段；旧 `images` 字段只为代码兼容，不用于新录入。
- 只接受仓库 `public` 内的 JPG、PNG、WebP。
- 附图已经通过版权和隐私确认后才可公开。

## 7. 录入馆主的话

`curator-notes.json` 使用：

```json
{
  "notes": [
    {
      "id": "opening-note",
      "date": "2026-08-31",
      "content": "榆野博物馆从这里开始。谢谢你来这里看看我们共同经历过的回忆。"
    }
  ]
}
```

新增一则时，在 `notes` 数组增加对象：

```json
{
  "id": "note-20260915",
  "date": "2026-09-15",
  "content": "<一两句话的短公告>"
}
```

页面会按日期倒序显示，不必手动调整数组顺序。`id` 发布后保持不变。

## 8. 校验与发布前检查

只校验内容：

```bash
npm run validate:content
```

完整构建：

```bash
npm run build
```

`npm run build` 会自动先执行内容校验。校验器主要检查：

- JSON 能否解析，顶层结构是否正确。
- 必填字段、字符长度和布尔字段类型。
- ID 格式与重复 ID。
- 馆藏名称和别名是否相互重复。
- 日期是否真实存在、时间是否带 `+08:00`。
- URL 是否为 http/https。
- 本地媒体是否存在于 `public` 且格式受支持。
- 失效来源是否有 `archiveUrl` 或 `archiveAsset`。
- 留言回复父级是否存在、时间是否倒置、关系是否循环。
- 意见的馆主回复是否早于意见。
- 是否误留 `isDemo` 字段或 `public/demo-*` 文件。

校验错误会写出类似 `keywords[0].nodes[1].sources[0].url` 的位置。修正所有错误后再提交和推送。

发布前还应人工确认：

1. 内容语境准确，没有把猜测写成事实。
2. 账号、平台和原链接与素材一致。
3. 图片替代文字能够说明画面。
4. 素材没有泄露个人信息。
5. 页面中实际点击过时间轴、音频、视频外链和来源反馈入口。
6. 手机和电脑端都检查过排版。

## 9. 不应写入公开数据的内容

- 尚未审核的留言、回复或意见。
- 被拒绝、隐藏或因风险删除的内容。
- 版权反馈中的真实姓名、联系方式、身份关系、证件或举证附件。
- GitHub 密码、访问令牌、Cookie 或任何账号凭据。
- 没有依据的传闻、为了补齐时间轴而猜测的日期。
- 仅用于测试页面的虚构馆藏、演示留言和 `demo-*` 文件。

V1.5 没有馆主后台。真实提交、审核、私密材料保存和自动发布必须等后续版本选定安全后端后重新设计，不能通过修改本指南绕过这一边界。
