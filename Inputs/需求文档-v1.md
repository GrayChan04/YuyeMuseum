## 1. 项目概述

### 1.1 一句话定位
榆野博物馆是**喻言粉丝自发建立**的线上展示馆，用来系统展示喻言及其粉丝群体之间的粉圈黑话和有意思的梗，帮助**新粉丝快速认识并了解喻言与喻言粉圈**。

### 1.2 核心价值
- 新粉入坑的"快速指南"：想认识喻言、看懂粉圈黑话的新粉，在馆里搜关键词即可看到该梗的完整发展脉络。
- 老粉的"档案馆"：把散落在各处的梗、图、切片用时间轴整理归档，成为可回溯的历史。

### 1.3 与既有项目的关系
独立新项目，与 YUYAN（喻言解谜游戏）无直接关系，不共用代码库、不共享数据。

### 1.4 非目标（v1 不做）
- 不做游客留言区、意见区（列入后续迭代）
- 不做搜索次数统计 / 自动 Top10（列入后续迭代）
- 不做投稿入口与审核后台（列入后续迭代）
- 不做馆主后台登录系统（列入后续迭代）
- 不接入外部数据库
- 不做多账号 / 多管理员

## 5. 页面规格

### 5.1 首页

**布局顺序（从上到下）：**
1. 馆名 / Logo（顶部）
2. 大搜索框（下滑页面后吸顶固定 sticky）
3. 热门关键词卡片区
4. 页脚

**搜索框行为：**
- 作为纯导航工具：输入关键词，实时匹配馆内已收录的关键词
- 匹配到 → 点击/回车跳转到对应关键词时间轴页
- 未匹配到 → 显示友好提示，例如"本馆暂未收录该词，日后投稿开放后可来补充"（为投稿机制埋下伏笔）
- 不记录、不统计搜索行为（v1）

**热门关键词卡片区：**
- 卡片式陈列（非纯标签平铺）
- 每张卡片内容：关键词名 + 一句话梗概 + 起始月
- 首版约 10 张卡片
- 点击卡片 → 进入该关键词时间轴页
- 排序依据：v1 为馆主手动排定（后续迭代：按搜索次数自动 Top10）

**移动端：**
- 页面在手机和平板（窄屏）下自适应，视觉语言与电脑端统一
- 吸顶搜索框在移动端同样生效

### 5.2 关键词时间轴页

**页面结构（从上到下）：**
1. 橱窗简介区
2. 纵向时间轴（节点列表）
3. 节点内容区（点击节点后显示）
4. 页脚

**橱窗简介区（时间轴页顶部）：**
- 该关键词是什么（一句话或一小段）
- 经典出处
- 俏皮的馆藏说明
- 显示时间范围：**只显示起始时间，精确到月份**（例："始见于 2020.03"）

**时间轴：**
- 纵向排布（上下滑动阅读）
- 时间粒度：**到月**即可（如 2020.03、2021.05），不需要精确到日
- 节点 = 圆点刻度为主，标注日期（年月）与标题
- 点击节点后，该节点内容显示在下方内容区
- 内容区展示的节点内容版式可灵活变化

**节点内容（点击后显示的内容组合，灵活选用）：**
- 简介文字（这段视频/事件/梗是什么）
- 出处：有明确出处 → 标注明确出处（链接/来源说明）
- 历史截图：无明确出处 → 放相关的历史截图
- 图片 / 表情包：有相关图 → 放图
- 视频 / 音频：如有切片或音频可内嵌
- 版式允许不同节点有不同排版

**布局（电脑与手机统一）：**
- 电脑与手机均采用"上时间轴节点 + 下内容区"的**上下布局**
- 手机端视觉语言与电脑端保持统一（视觉一致，非像素级要求）
- 点击节点后内容**进来即全文展开**（不做"先简介后收拢"）

### 5.3 关于本馆页

**内容定位：**
- 不介绍馆主个人
- 说明：榆野博物馆是粉丝独立运营的线上展示馆，用来展示喻言及喻言粉丝相关的粉圈黑话和有意思的梗
- 目的：让新粉快速认识并了解喻言与喻言粉圈
- 页面风格与全站一致，简洁留白

```jsonc

  "keywords": [
    {
      "id": "keyword-slug",          // 唯一标识，用于路由

      "startTime": "2020-03",        // 起始月，YYYY-MM
      "intro": "橱窗简介文字",
      "origin": "经典出处说明",
      "curatorNote": "俏皮馆藏说明",
      "nodes": [ "节点id1", "节点id2" ]
    }
  ]
}
```

### 6.2 时间轴节点数据（示例）
```jsonc
// nodes.json — 所有节点
{
  "nodes": [
    {
      "id": "node-id",
      "keywordId": "keyword-slug",
      "time": "2020-03",              // 年月
      "title": "节点标题",
      "body": "简介文字...",
      "source": {                     // 出处（可选）
        "label": "来源名称",
        "url": "https://..."
      },
      "images": ["/assets/img1.png"], // 截图/图片/表情包（可选）
      "media": {                      // 视频/音频（可选）
        "type": "video",
        "url": "https://..."
      }
    }
  ]
}
```

## 7. 技术与部署

### 7.1 技术栈
- 前端框架：**Vite + Vue 3**
- 内容存储：**Git 仓库内 JSON 数据文件**（版本可控、可回滚；不接入外部数据库）
- 路由：Vue Router

### 7.2 部署
- 平台：**GitHub Pages**
- 仓库：**独立新仓库**（如 `YuyeMuseum` 或等同名仓库）
- 域名：**不使用自定义域名**，使用 GitHub 默认地址（`用户名.github.io/仓库名`）
- CI/CD：**GitHub Actions 自动构建部署**——push 到 main 即自动 build 并发布到 Pages

### 7.3 响应式要求
- 同时支持电脑网页端与手机移动端
- 窄屏（手机/平板）自适应布局
- 视觉语言全端统一

## 8. 后续迭代详细需求（规划存档）

> 以下为已确认的后续规划，v1 不实现，开发时留出扩展空间（数据字段、路由结构便于扩展即可）。

### 8.1 留言区 / 意见区
- 同一社区页面下的两个分区（标签切换）：留言墙 + 意见箱
- 公开 vs 匿名：用户自愿留昵称则公开展示昵称；匿名则不显示昵称
- 零门槛，不采集访客身份
- 留言墙：完全自由，提交即所有人可见
- 意见箱：意见同样公开可见

### 8.2 搜索统计 + 热门 Top10
- 记录搜索次数
- 通过定时任务（如 GitHub Actions 每日）自动重算 Top10 并更新热门关键词

### 8.3 投稿 + 审核
- 开放游客投稿（新关键词 / 新节点）
- 馆主审核后放行 / 驳回 / 编辑

### 8.4 馆主后台
- 独立管理入口（不在游客端 UI 体现）
- 登录：单账号密码（暂不做多管理员）
- 职责：
  - 投稿审核
  - 留言管理（删除违规、置顶、馆主回复）
  - 意见管理（查看、回复全部意见，标"已处理/已采纳"）
  - 内容管理（增删改关键词、时间轴节点、图片文字）
- 意见：不做删除；馆主公开回复所有意见；已回复的标"已处理/已采纳"标签

## 9. 验收标准（v1）

1. GitHub Pages 线上可访问「首页」「关键词时间轴页」「关于本馆页」三个页面
2. 首页：Logo/馆名、吸顶大搜索框、热门关键词卡片区（约 10 卡）均正常展示
3. 搜索：输入关键词可匹配并跳转时间轴页；未命中给出友好提示
4. 时间轴页：橱窗简介 + 起始月显示；纵向时间轴圆点节点；点击节点后下方内容区全文显示
5. 节点内容支持：文字 / 出处链接 / 截图 / 图 / 表情包 / 视频 / 音频
6. 整体视觉：黄绿暖黄调、极简艺术馆风、全站协调统一；Logo（YUYE 房子形）展示
7. 电脑与手机均可正常使用，布局自适应，视觉语言一致
8. 顶部导航（首页 | 关于本馆）与全局页脚（含版权声明文案）全站生效
9. push main 后 GitHub Actions 自动构建并部署
