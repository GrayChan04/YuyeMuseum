# 榆野博物馆 · 项目需求文档 v1.3

> 版本：v1.3（2026-08-29）
> 状态：需求已确认，进入开发
> 维护者：馆主
> 版本说明：本文件完整继承 v1.2 的内容、数据与技术边界，并以本轮确认的品牌、统一版头、首页重复吸附、馆藏双栏介绍和时间轴视觉优化为最新准则。旧版本继续保留作为历史记录。

## 1. 项目目标与版本边界

榆野博物馆是由喻言粉丝自发建立的线上展示馆，以关键词和时间轴整理喻言与粉丝群体之间的梗、出处及共同记忆，帮助新朋友理解相关语境，也为一路相伴的朋友保存值得记住的片段。

V1.3 是 V1.2 的视觉与交互优化版本，不扩张业务能力：

- 继续展示四件虚构演示馆藏，不编造真实粉圈历史。
- 继续通过小草坪演示留言、回复、匿名意见及馆主回复的未来形态。
- 留言、意见和版权反馈表单仍然禁用，不发送或保存访客输入。
- 不接入数据库、账号系统、馆长后台、统计系统或第三方提交服务。
- 继续使用 Vue 3、Vite、Vue Router、JavaScript、仓库内 JSON 和 Hash 路由。
- 继续由 GitHub Actions 构建并发布到 GitHub Pages。

## 2. 页面、导航与品牌

### 2.1 页面路径

| 页面 | Hash 路径 | 主要内容 |
|---|---|---|
| 首页 | `/#/` | 品牌版头、搜索、部分馆藏 |
| 馆藏详情 | `/#/keyword/:id` | 馆藏介绍、横向时间轴、节点详情 |
| 小草坪 | `/#/lawn` | 留言墙、意见箱、筹备中表单 |
| 建馆说明 | `/#/about` | 建馆用途、版权立场、三条准则 |

未知路径和不存在的馆藏继续显示站内 404。既有 URL、路由名称和浏览器标题规则不变。

### 2.2 固定导航

- 导航固定在视口顶部，页面内容、吸顶搜索和其他 sticky 元素不得被遮挡。
- 右侧仅保留 `首页 / 小草坪 / 建馆说明` 三个入口。
- 左侧品牌入口同时显示新版 Logo 和中文馆名 `榆野博物馆`，电脑与手机均不隐藏馆名。
- Logo、馆名组成一个返回首页的可点击区域；在首页再次点击时平滑回到顶部。
- 当前页面仍只用颜色和字重表示，不增加下划线或新的装饰编号。
- 保持桌面约 68px、常规手机约 60px 的导航高度；360px 及以下可改为两行、约 94px 的紧凑导航，确保馆名与三个入口在 320px 和高倍放大场景下均不被裁切。

### 2.3 YUE 博物馆 Logo

- 保留 `Y` 位于左侧、`U` 位于右上、`E` 位于右下的既定关系。
- 第一眼应能理解为极简博物馆立面，第二眼可辨认 YUE。
- Y 的双臂承担山花与屋檐方向，主干承担左侧承重结构。
- U 的竖笔与弧形承担立柱、回廊或拱门结构。
- E 的竖笔与三条横笔承担展层、楼板和基座台阶。
- 字母笔画自身组成建筑，不在外部套独立房屋轮廓。
- 使用单色深绿、简洁圆角连接和适合小尺寸的较粗笔画；不使用阴影、渐变或复杂填充。
- 导航、favicon 继续使用同一份 SVG 图形。

## 3. 全站统一布局系统

### 3.1 统一版头

首页、小草坪、建馆说明和所有馆藏详情使用同一个响应式版头高度规则：

- 常规屏幕的目标高度按“首屏 70% 减去导航高度与约半个搜索栏高度”计算。
- 桌面限制在约 380–720px，手机限制在约 380–560px。
- 同一视口下四类页面的版头高度一致；在辅助字号放大或内容确实放不下时允许自然增高，不能裁掉正文。
- 桌面采用左侧文字、右侧主题场景的基本网格；手机改为单列，场景缩小、下移或淡化为背景。

版头统一几何，不使用同一张背景机械复制：

- 首页：温暖的展馆入口、展灯和建筑光影。
- 小草坪：现有绿色草景。
- 建馆说明：图纸、档案纸和整理痕迹。
- 馆藏详情：右侧资料本身形成展灯下的展签。

所有纯装饰场景使用轻量 SVG/CSS，不能阻碍文字操作，并从辅助技术中隐藏。

### 3.2 统一内容宽度

- 导航内层、四类版头内层、搜索、部分馆藏、小草坪主体、建馆准则、馆藏介绍和时间轴统一到最大 1180px 的外框。
- 删除作用在主要可见外框上的 930px、900px 等额外限制，保证各页面左右边线一致。
- 长篇正文、媒体说明可以在统一外框内部保持约 68 字符或 760px 的舒适阅读宽度。
- 统一版头之后的主内容上、下间距；手机端适当缩短，但页面之间使用同一套节奏。

## 4. 首页

### 4.1 版头内容与构图

- 首页改为左文右景，而非居中排版。
- 左侧依次显示：
  1. 中等字号馆名 `榆野博物馆`；
  2. 两行大字 `把共同记得的事， / 一件件收藏起来。`；
  3. 一行小说明 `从一个关键词出发，沿着时间线重新遇见它的出处、变化与回声。`。
- 馆名、大标语和小说明都使用正字距。参考值分别约为 `0.16em / 0.055em / 0.08em`；手机端缩小正字距与字号，保证 320px 不溢出。
- 右侧使用简洁的展馆入口、展灯、台阶和树影场景，不增加英文眉题、装饰编号或按钮。

### 4.2 搜索位置与外观

- 搜索仍是版头之后的独立区域，不能嵌套进版头，否则 sticky 会被版头边界限制。
- 初次打开首页时，搜索框的视觉中心约处于首屏 70% 的中下位置，并保持清楚可见。
- 搜索吸顶后停在固定导航正下方，并在首页内容范围内保持吸附。
- 删除搜索区域底部横贯页面的分隔线。
- 保留搜索输入框自身的下划线、图标、候选和无结果反馈。
- 不使用明显阴影重新制造一条新的全宽分隔线。

### 4.3 可重复向下吸附

- 搜索吸附不再是一次性行为。
- 页面在首页版头内时，累计约 24px 的向下滚轮或触摸移动，即平滑滚到搜索栏贴住导航的位置。
- 用户手动向上返回版头、进入吸附目标上方约 64px 后，下一次轻微向下滚动必须再次触发相同吸附。
- 不实现向上自动翻页；浏览馆藏区时不得抢夺普通滚动。
- ArrowDown、PageDown、空格与向下手势行为一致；输入框、按钮、链接等交互元素获得焦点时不得拦截按键。
- 动画期间防止重复触发；旋转屏幕或改变视口后重新按稳定的文档锚点计算目标。
- 开启 `prefers-reduced-motion` 时保留定位行为，但取消平滑动画。

### 4.4 部分馆藏

四件馆藏、搜索规则、卡片字段和响应式列数继续遵循 v1.2，不在本轮改变数据与内容。

## 5. 馆藏详情与时间轴

### 5.1 左右介绍版头

- 桌面左侧显示返回入口、馆藏名称和简介。
- 右侧显示始见月份、别名、经典出处，排成一张有轻微展灯光影的展签。
- 右侧出处有 URL 时继续可点击并在新标签页打开；无 URL 时显示普通文字。
- 手机端按“返回入口 → 名称与简介 → 信息展签”的顺序堆叠。
- 删除馆藏介绍与时间轴之间横贯整个页面的分隔线，以背景和留白完成过渡。

### 5.2 横向时间轴

- 时间轴保持单行横向排列，节点按时间从早到晚排序；溢出时允许横向滚动，不带动整页横溢。
- 日期、圆点和标题以每个节点中心对齐。
- 每个节点使用同一条轨道行同时绘制连接线和圆点，连接线必须穿过圆点的几何中心，不再分别硬编码高度。
- 删除时间轴列表的顶部边线、底部边线和节点之间的竖分隔线。
- 时间轴自身只保留一条连接所有圆点的主横线。
- 悬停、键盘聚焦和选中只改变圆点、标题颜色及字重，不给整个节点列铺背景。
- 初始不展开详情；点击展开、重复点击收起、点击其他节点切换的行为不变。
- 按钮的 `aria-expanded`、`aria-controls`、焦点管理和横向自动露出行为继续保留。

### 5.3 展开详情

- 展开详情的外框改为与 1180px 主要边界对齐，正文与媒体在内部收窄。
- 按馆主确认，保留详情面板顶部和底部的外边线。
- 按馆主确认，保留详情标题下方的局部短分隔线。
- 图片、本地音频、视频外链、来源、动画和媒体停止规则继续遵循 v1.2。

## 6. 小草坪与建馆说明

### 6.1 小草坪

- 小草坪接入统一版头高度和 1180px 外框。
- 保留绿色背景、标题、现有说明和草景，调整草景比例以适配新高度。
- 留言墙、意见箱、键盘标签切换、三层回复、馆主回复、禁用表单等行为与内容不变。

### 6.2 建馆说明版头

- 版头左侧显示标题及两段文字，右侧显示档案纸与建馆图纸场景。
- 第一段保留当前用途说明，并在“那些曾经鲜亮的回忆。”处结束。
- 第二段必须独立成段，固定为：

  > 本馆与艺人本人及经纪公司无关；馆内素材版权归原作者所有，馆中所藏来自有限的记录与视角，只是共同记忆的一隅，不代表完整故事。

### 6.3 三条建馆准则

版头下使用三张无编号档案便签。桌面三列，手机单列。文案固定为：

1. **核实后入馆**：每条馆藏尽量核对发生时间、原始出处和上下文；暂时无法确认的内容会明确标注，不作为定论。
2. **清楚标注出处**：图片、音频、视频和文字资料尽量注明原平台、发布账号与可访问链接，方便查证和版权反馈。
3. **对新朋友友好**：用简明介绍、别名说明和时间轴补足背景，不把熟悉粉丝语境当作阅读前提。

列表在视觉上不显示编号；文档中的编号仅用于说明三条内容。

## 7. 接口、数据与兼容性

- `keywords.json`、`community.json` 的字段结构保持不变，不进行迁移。
- 首页、馆藏、小草坪、建馆说明和 404 的路径保持不变。
- 搜索名称/别名、时间轴排序、节点媒体、来源链接、留言树和意见排序规则保持不变。
- 不添加新的 npm 依赖；新版 Logo 与页面场景使用仓库内 SVG/CSS。
- 支持当前主流 Chrome、Edge、Safari、Android/iOS 浏览器和微信内置浏览器，不支持 Internet Explorer。
