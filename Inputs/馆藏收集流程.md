# 馆藏收集流程

## 启动与交付

“收集馆藏：名词”新建研究；“补充馆藏：名词”读取原研究和馆主决定后续查；“确认入馆：名词”仅批准本次呈交的明确版本和节点。指代或批准范围不清楚时先询问。

研究保存在 `Research/<稳定英文ID>.json`，截图放 `Research/evidence/<ID>/`。此目录被 Git 忽略，但不是加密存储，不记录登录凭据或不必要的个人信息。正式节点写入 `src/data/keywords.json`，并遵循 `src/data/keywordTemplete.json` 的“馆藏名称作键”数组格式。

## 搜索与核对

1. 辨认名词的对象、别称、账号及相互关系。“二踢脚”以账号及其人格设定为核心，不预设属性属于喻言本人。
2. 主要搜索微博和 B站：起源、含义、生日、身高、作品、互动、二创、称呼变化。沿来源引用追溯其他平台；账号的无关 @ 提及不作为节点。
3. 逐条记载检索词、访问日、检索结果和访问限制。搜索摘要是线索，完整原帖文字、视频实际片段与标题简介区分记录；不把未观看的视频说成已观看。
4. 事件日期、发帖日期、采集日期分开，未知值用 null。不把最早搜到的结果说成已经证明的起源。
5. 新增信息、含义变化和有证据的重要传播作为候选节点；重复转发作为同一事件的佐证。前因后果分别标明来源明确说明或研究推断，关联只引用已有候选 ID。
6. 属性冲突、权威性和推断交馆主判断，保留所有候选说法和出处，不自动选择最新说法。其他研究继续推进。馆主决定记录日期、范围、理由；新材料不得覆盖已有决定。
7. 覆盖关键方向并跟进引用后，连续两轮未出现新增重要线索可结束本次检索。访问失败不能当作无记录；明确记录受阻方向。每轮输出新增线索和未解问题。

## 凭证

每个节点努力获取实际出处截图：保留足够上下文、账号、日期，另记原链接及采集时间。视频截图记录时间码。馆主提供的截图标注提供方式及独立核实情况。禁止生成或重排文字伪造截图。

截图不足先待补证。馆主无法补图且明确决定保留时，才允许 evidence.status=missing、missingApproved=true，并记录缺图放行决定。网页原样显示：“该节点凭证缺失，馆主并未找到，有凭证者可联系馆主进行补充”。

截图缺失与内容可信度独立记录。不确定说法经馆主批准后可入馆，但必须有 uncertainty 公共说明。未能确定日期的节点继续留在研究记录，不编造时间来满足时间轴。

## 研究 JSON 约定

顶层：schemaVersion=1、id、name、scope、aliases、searchedAt、searchLog、sources、candidates、decisions、questions、publication。

sources 每项包含 id、url、platform、account、publishedAt（未知 null）、access（snippet/text/video/blocked）、notes。所有 id 使用稳定小写字母数字及连字符。

candidates 每项包含 id、eventDate（未知 null）、claims、sourceIds、relations、review（pending/approved/rejected）、decisionId、uncertainty、displayNode。claims 为说法数组；relations 每项含 targetId、kind、basis（explicit/inferred）和说明。displayNode 为现有节点结构；未到展示准备阶段可为 null。

decisions 每项含 id、actor=curator、date、candidateIds、action（approve/reject/allow-missing）、reason。只根据用户真实答复填写；缺图放行单独记录。

publication 包含 review、decisionId、keyword。研究稿中的 keyword 只作为审批元数据，nodes 必须留空，由导出程序根据获批候选转换为正式模板格式；未准备好时 keyword=null。导出不会把研究稿中的内部 ID 写进正式模板。

displayNode.evidence 包含 status、screenshots、missingApproved。截图每项含 src（正式 public 相对路径）、alt、sourceId（指向该节点 sources 的 ID）、capturedAt、providedBy（researcher/curator）、publishedAt（未知 null）、timecode（视频时必填）、medium（post/video）。不重复塞入 images。

## 审阅与入馆

交稿展示候选时间轴、各说法证据、缺图情况、待决问题及可公开文案，生成草稿，不默认发布。研究验证：`npm run validate:research -- Research/<ID>.json`。

馆主批准明确版本后记录决定，复制获批截图到正式资源目录（例如 `public/media/<ID>/evidence/`），生成正式凭证路径。执行 `npm run export:collection -- Research/<ID>.json` 先检查预览，确认导出内容符合批准范围后加 `--write` 写入。紧凑模板按馆藏名称、节点日期和标题合并，排除项不会自动删除已发布内容；删除另需馆主明确要求。导出前会校验完整合并结果，失败不改正式文件。

再运行 `npm run build`、`git diff --check`，检查页面与图片，提交正式代码/数据/媒体并推送。不得把 Research 加入提交。检查 GitHub Actions 对应提交部署结果；无法读取时如实报告“推送完成，部署未验证”。

意见、评论和补充凭证入口目前为原型，不发送、不保存，不以其收集到资料作为流程依据。
